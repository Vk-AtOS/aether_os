Running AetherOS Offline: Air-Gapped AI App Generation

Healthcare, finance, and defence teams cannot send source specs to cloud APIs. Here is how AetherOS generates production apps entirely inside your firewall.

Thulasi Velan March 5, 2026 7 min read

The Problem With Cloud-Only AI Generation

When a regulated enterprise wants to generate a custom internal application — a patient records system, a trading desk tool, a procurement portal — the first question from the CISO is always the same: "Where does our specification data go?"

For most AI platforms, the honest answer is: to a cloud API, across the public internet, through a third-party's servers. For a healthcare provider operating under HIPAA, or a defence contractor with classified project names, that answer ends the conversation before it starts.

AetherOS was designed from the ground up so this is never the answer. The 39-phase pipeline can run entirely within your infrastructure, touching no external API, with zero data egress.

What "Offline First" Actually Means

Offline-first is not a marketing claim — it is an architectural constraint that changes every design decision. In AetherOS edge mode:

  • All language model inference runs via Ollama, hosted inside your datacenter or private cloud.
  • The model registry is pre-seeded — Mistral 7B, Llama 3.2, DeepSeek-Coder — and pulled once during setup, never again.
  • Code generation, test writing, security review, and compliance reporting all execute locally.
  • The only outbound traffic is what your generated app intentionally makes — never the build pipeline itself.

The 39-Phase Pipeline Without Internet

AetherOS breaks app generation into 39 discrete phases — from specification parsing through frontend polishing and final deployment. In cloud mode, a handful of these phases call out to Anthropic or OpenAI APIs for complex reasoning tasks. In offline mode, those same calls route to local Ollama endpoints instead.

The switch is a single environment variable: 

# .env — switch the entire pipeline to local inference
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=deepseek-coder:6.7b

# The 39-phase orchestrator reads this and routes accordingly
# No other config change needed

We benchmarked this configuration on a 32-core server with 128 GB RAM. The full pipeline — from spec to running Docker containers — completed in 38 minutes on average, versus 22 minutes in cloud mode. For teams where data sovereignty is non-negotiable, 16 extra minutes is a trivial tradeoff.

Why Regulated Industries Demand It

Three sectors come up in every enterprise AI conversation:

  • Healthcare: Patient data, even in aggregate, cannot leave a compliant environment. The spec for a patient-facing appointment app may contain field names, data schemas, and workflow logic that qualifies as protected health information.
  • Finance: Trading logic, risk models, and client segmentation rules are material non-public information in some jurisdictions. Sending them to an external API — even for code generation — creates regulatory exposure.
  • Defence and government: Classified project names and system architectures cannot be transmitted outside an accredited boundary. Full stop.

AetherOS edge mode is the answer for all three. The generated app lives inside your boundary. The generation process lives inside your boundary. Audit logs are local. Nothing leaves.

Performance: Local Models vs Cloud Models

The common assumption is that local models produce inferior output. For general-purpose creative tasks, this is sometimes true. For structured code generation — which is what AetherOS does — the gap is far smaller than most people expect.

DeepSeek-Coder and CodeLlama consistently produce syntactically correct FastAPI routers, Pydantic models, and React components. The quality difference shows up in edge cases: complex join logic, nuanced security review, multi-service orchestration. For those specific phases, AetherOS edge mode uses a hybrid approach — the reasoning-heavy phases can optionally call an on-premise fine-tuned model, while code synthesis phases use the smaller general model.

The result is a generation pipeline that is 85–92% as capable as the cloud version for the vast majority of enterprise internal apps — and 100% compliant for air-gapped deployments.

Setting Up AetherOS in an Air-Gapped Environment

The setup process is designed to work without any internet access after the initial image pull:

  • Pull the AetherOS Docker image and the Ollama model weights to a staging machine with internet access.
  • Transfer images to the air-gapped network via approved media (USB, internal registry).
  • Deploy with docker-compose using the offline configuration profile.
  • All 39 pipeline phases run without modification — the provider abstraction layer handles routing transparently.

Our deployment team provides an offline setup runbook and validation checklist for enterprise customers. The typical time from image delivery to first successful app generation is under four hours.
