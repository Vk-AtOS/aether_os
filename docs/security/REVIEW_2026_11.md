# Security review, November 2026 (KAN-69)

Date: 15 Nov 2026. Tree: AetherOS branch `r3/a_docs` (off `r2/int`, base e5c23fd). Velaris was read at `wt2/int` (branch `r2/int`), read only.

## How this review was done

- Four independent reviewers read the code without trusting earlier reviews or code comments: AetherOS gateway, AetherOS core and deploy files, generated code and pipeline phases, and Velaris plus the signed-identity proxy.
- The route table was built by importing the app (656 rows). Every non-Velaris route has a guard identified (public, authenticated, role floor, admin, superadmin, or run/org scoped).
- Each finding was traced from entry point to sink. CONFIRMED means the whole path was traced. PLAUSIBLE means one step was not verified, and the step is named.
- Nothing was run against a live server, a real Postgres, nginx, Docker or a model. Dependency CVE status is "not measured" (needs `pip-audit` and `npm audit`, both need network).
- No secret value appears in this file.

## Prompt-injection chains (pipeline)

Repo import (`/factory/fetch-repo`, `/fetch-github-repo`) and user spec text flow into the requirement text, the model writes the IR, and then table, workflow and event names reach file paths and source (G5, G6). The p04a path validates identifiers; p04b and p05 do not.

## Where code of untrusted origin runs

In production (`ENVIRONMENT=production`) the sandbox runner refuses the host and macOS backends (`core/sandbox/runner.py:150-174`) and uses Docker: non-root, capabilities dropped, read-only root, resource limits, an allow-listed environment (`core/run_app/child_env.py:16-23`), separate no-egress and egress networks. Host-side exceptions: the p05 screenshot (a Chromium on the host loads generated JavaScript, PLAUSIBLE), `bandit` and `pip-audit` on generated files (SC-04), the Railway CLI call with the full environment (`p11_deployment/helpers.py:237`), axe on the host. Not tested live: tenant isolation inside the sandbox, the host firewall script.

## Supply chain

- `requirements.txt`: 64 lower-bound specs without hashes. `requirements.lock`: 63 exact pins of direct dependencies only (transitive dependencies are not pinned), no hashes.
- Declared but not locked: ldap3, mcp, prometheus-fastapi-instrumentator, psycopg2-binary, pytest-json-report, stripe, whatthepatch. The production image installs the lock only (`Dockerfile:24-29`), so those packages are absent from the image. Whether the features that need them work in the image was not run.
- Base images are pinned by digest. `dashboard` has a lockfile and uses `npm ci`; `vscode-extension` has no lockfile.
- Licences: `psycopg2-binary` is LGPL (dynamic link). Semgrep is left out as a system tool. Installed-package licence metadata and copied AGPL headers were not checked: not measured.
- CVE status: not measured. Commands: `pip-audit -r requirements.lock`, `npm audit --omit=dev` in `dashboard/` and `vscode-extension/`.
- Workflows: `ci.yml` has `contents: read`; actions are pinned to tags, not commits. `aetheros-generate.yml` has write scopes behind a maintainer label and passes issue text through env.

## Checked and found sound (control and location)

- Auth pipeline: revocation, role and org re-read from the database each request, MFA-pending rejected (`gateway/dependencies.py:35-146`).
- Token types separated (`gateway/auth.py:240-251`); refresh rotation with reuse detection (`gateway/auth_refresh.py:139-168`).
- Password reset and verification tokens, API keys (hash, org binding, role `api` blocked from admin routes).
- Webhooks: Stripe `construct_event` before parsing; Razorpay HMAC with `compare_digest`; CI webhook fail-closed; outbound webhooks pinned against SSRF (`core/security/safe_http.py:29-98`).
- SCIM: org from the token, filters regex-validated.
- Role gate matches on the route template (case and trailing slash safe), unknown roles denied (`gateway/role_gate.py:57-79`).
- Run-scoped routes check org; file paths go through `safe_fs`; superadmin routes need `superadmin`.
- Git clone validation for the pipeline (`phases/p03_scaffolding/validation.py:23-43`).
- Docker sandbox policy (`core/sandbox/docker_backend.py:87-130`); no `shell=True`, no pickle, `yaml.load`, `eval` on dynamic data in the non-HTTP code.
- Generated apps (p04a IR path): RS256, bcrypt, role model per decision D1, tenant filters on every CRUD path, pagination cap 200, no f-string SQL, explicit CORS list, identifier checks on entity, table, field and enum names.
- Ledger: per-org hash chains, signed checkpoints, key file mode 0600 (`core/audit/checkpoints.py:93-107`).
