# Dead-code review (KAN-171)

Re-derived on `main` at b43c4a6 (22 Nov 2026). This is the decision table; the earlier evidence report is `docs/dead_code_report.md` (15 Nov), whose per-item greps still apply. Velaris has its own `docs/DEAD_CODE_REVIEW.md` in that repository.

## Method

1. Import graph over every tracked `.py` file (`ast`, absolute and relative imports, `from pkg import module`). Tests never count as callers. Roots: `main.py`, `seed_db.py`, `gateway/api.py`, `cli/`, `scripts/`, `alembic/`, `deploy/`, and any module named in a YAML, TOML, shell, Dockerfile, compose, Helm, Terraform or CI file.
2. Dynamic loading added as edges: dotted-path strings in code, `importlib` f-strings of the form `aether_os.phases.{name}.task_agent` (a phase directory counts as loaded when its name appears in non-phase production code), `PHASE_SUPERVISORS`, the router loader in `gateway/api.py`, `core/domain_knowledge/loader.py`.
3. For each module left over: a search of every tracked text file (code, tests, docs, YAML, shell) for the dotted path, `dir/file` and its symbols. The generated `docs/codebase_map/` and `docs/archive/` pages are not counted as references (they list every file).
4. Classes: **DELETE** = zero references anywhere, no test other than its own, not a documented capability, and superseded, duplicated, empty or a stub. **KEEP-AS-TOOL** = standalone library or helper with tests or documentation. **WIRE-LATER** = a real feature or control that is written but not connected; not wired here.
5. Left out on purpose: phase-loaded modules (task_agent, supervisor_agent, prompts, helpers of phases named in `stages/`), domain packs (loaded by name in `core/domain_knowledge/loader.py`), and classes or functions inside live modules (see `docs/dead_code_report.md`, "Below module level").
