# Blast radius: what still works when one thing is down (KAN-52)

Design table, generated by `python3.11 scripts/fault_injection.py --table` and kept in sync by a test.
"up" = answers 200, "refused" = 503 on purpose (fails closed or a named dependency is missing), "down" = no answer.

| stopped | healthz | readyz | authed read | velaris | preview |
|---|---|---|---|---|---|
| (nothing) | up | up | up | up | up |
| db | up | refused | refused | refused | up |
| redis | up | refused | refused | refused | up |
| velaris | up | up | up | refused | up |
| preview | up | up | up | up | down |
| api | down | down | down | down | up |
Notes:

* **Redis down refuses authenticated calls** (503): the token revocation check fails closed. This is deliberate (a revoked token must
  never be accepted because the store was down). Cost: Redis is on the critical path of every signed-in request, so it needs a
  replica and automatic failover (`docs/ops/CLOUD_REFERENCE_ARCHITECTURE.md`).
* **Postgres down** makes `/readyz` 503 so load balancers stop sending traffic, and authenticated requests answer 503 with
  `Retry-After: 5` instead of a 500 with a stack trace. The preview server needs neither database nor Redis.
* **Velaris down** costs only the Velaris pages: calls fail fast after 5 failures for 30 s (breaker), at most 32 wait at once
  (bulkhead), `/readyz` stays 200 and names `velaris` as degraded; the dashboard shows it.
* **LLM down**: runs that need a model fail or wait, everything else keeps working: sign-in, approvals (Prime inbox), reads.
  New pipeline runs queue when the SQS queue is configured; without a queue they start and fail at the first model call (gap:
  admission should refuse or queue explicitly, to be ticketed after the first live run).
* The compose version of this table (stop each container, probe) is `scripts/fault_injection.py --run --token ...`. It needs
  Docker and a running stack and has NOT been run here: the Docker daemon was not available.
